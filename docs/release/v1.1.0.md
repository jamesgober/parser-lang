# parser-lang v1.1.0: depth and error limits

**Minor.** Deep or hostile input now ends in a result or a recorded error
instead of a stack overflow, and the error log can be capped. Everything in
1.0 still works the same way; the additions are new methods on `Parser`.

## No recursion for infix operators

The Pratt driver used to call itself once for each right operand. A
left-associative chain stayed shallow, but a right-associative one (`a = b = c
= ...`, `2 ^ 2 ^ 2 ^ ...`) went one stack frame deeper per operator, and about a
million of them aborted the process with a stack overflow.

`Pratt::expression` now keeps pending operators on a heap stack. It makes the
same grammar calls in the same order as the recursive version, so every grammar
gets the same results, and a chain of any length parses in constant stack space.
A property test holds the new driver to the old one over random binding tables
and token streams. On the benchmark expressions it is also 5 to 20 percent
faster, since a right operand that is a single atom is combined at once.

## Depth limit

Nesting through `prefix` still uses the call stack: a parenthesized group or a
prefix operator calls `expression` again from grammar code. `expression` now
counts those levels against the parser's depth limit. Past it, it records
"expression nested too deeply" at the current token and returns `None`.

The default is 256 levels, which fits in a 1 MiB thread stack in a debug
build. Set it with `Parser::with_depth_limit`, and raise it only when the parser
runs on a thread with a bigger stack.

## Error limit

`Parser::with_error_limit(n)` stores at most `n` errors. Later ones are
counted in `Parser::omitted_errors` and still make `has_errors` true, but they
are not kept, so a grammar that records one error per token on a large garbage
file uses bounded memory. `Parser::new` keeps every error, as before; set a
limit whenever the input is untrusted.

## Upgrading

Nothing to change. A grammar that legitimately nests expressions more than 256
levels deep needs `with_depth_limit` with a higher value (and a stack to match).

MSRV is unchanged at Rust 1.85.
